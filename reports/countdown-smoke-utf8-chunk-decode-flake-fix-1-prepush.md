## 2) السبب الجذريّ — **خطأ في عميل HTTP داخل الاختبار، وليس في السيرفر**
دالّة `get()` كانت تجمع جسم الاستجابة هكذا:
```js
let b = ''; res.on('data', c => b += c);   // c = Buffer (لا encoding)
```
`b += c` يفكّ ترميز **كلّ chunk على حدة** عبر `Buffer.toString()`. عندما ينقسم محرف UTF-8 متعدّد البايتات (مثل التركيّة `ı`=‏`C4 B1`، أرقام بنغاليّة، الإسبانيّة `í`، الحروف العربيّة) **على حدّ chunk**، تتحوّل البايتات المقسومة إلى `�` (U+FFFD). موضع الانقسام يعتمد على توقيت الشبكة/الكتابة ⇒ **تذبذب**، ويُصيب اللغات غير-ASCII فقط (الإنجليزيّة لا تتذبذب أبدًا).

**الدليل المُلتقَط** (الرياض/tr، نفس الطلب):
```
JSON-LD answer : "Beklenen Hicri Yılbaş��na 354 gün kaldı."   ← �� مكان ı
VISIBLE answer : "Beklenen Hicri Yılbaşına 354 gün kaldı."    ← ı سليم
الرقم 354 متطابق في النسختين  ⇒  ليست مشكلة قيمة/وقت، بل بايت UTF-8 مقسوم.
```
أي أنّ السيرفر يُصدِر UTF-8 سليمًا؛ **الاختبار يُفسده عند القراءة**. لذلك يقارن التحقّق نسختين من نفس نصّ الإجابة (المرئيّة مقابل JSON-LD)، وأيّ تلف في إحداهما يكسر `includes()`.

## 3) الإصلاح
جمع الـ Buffer chunks وفكّ ترميز **مجرى البايتات كاملًا مرّة واحدة**:
```js
const chunks = [];
res.on('data', c => chunks.push(c));
res.on('end', () => resolve({ status: res.statusCode, body: Buffer.concat(chunks).toString('utf8') }));
```
مع تعليق يشرح سبب عدم العودة إلى `b += c`. هذا الإصلاح **حتميّ** ولا علاقة له بالوقت، ويُحصِّن **كلّ** تحقّقات المجموعة ضدّ نفس التلف — دون **تخفيف** أيّ تحقّق ودون لمس السيرفر.
